# stowage_kit_check (Resource)

Proves a kit was taken: the issuing install's `kit check HANDOFF INSTANCE` (Kubernetes: `k8s kit check`; VM: `sudo -n <short_name>-stow kit check`), run at create and again every poll while it answers unknown (its exit 2, or no answer: ssh, sudo or the installer failing), until it says proven or not proven or `timeout` runs out. `proven` records it; by default not proven, or no verdict by the timeout, is an error (`fail_if_not_proven`). A refresh runs the check once more while `proven` is false, so a later plan sees a proof that came after. Destroying it runs nothing.

## Example Usage

```terraform
# The issuer proves site B took its kit: `kit check second-site site-b`, tried until it answers.
resource "stowage_kit_check" "site_b" {
  handoff  = stowage_kit.site_b.handoff
  instance = stowage_kit.site_b.instance
  triggers = { kit = stowage_kit.site_b.id }
  timeout  = "10m"

  kubernetes {
    installer = stowage_kubernetes_install.issuer.installer
    namespace = stowage_kubernetes_install.issuer.namespace
  }

  lifecycle {
    replace_triggered_by = [stowage_kubernetes_install.site_b] # a replaced target keeps its id
  }
}
```

## Details

The install that issued the kit is named by one block, as `stowage_kit`'s. `handoff`, `instance`,
`triggers` and what names the install replace the resource; `timeout`, `fail_if_not_proven` and how
the install is reached change in place, running nothing.

**Create**: the issuing release's `describe --json` (as `stowage_kit`'s, with its refusals: `No install there`, `No release there`, `The release runs another installer`) must list `handoff` (`No
such handoff`) with a check (`A handoff without a check`: its `kit check` would answer unknown every
time), else an error before any check runs. Then each run: Docker, the kept installer's `kit check HANDOFF
INSTANCE --dir`; Kubernetes, `<name>.sh k8s kit check HANDOFF INSTANCE --namespace …` by the release's
own installer (as `stowage_kit`'s); VM, `sudo -n <short_name>-stow kit check HANDOFF INSTANCE` over
SSH. Exit 0 with its line `HANDOFF INSTANCE: proven` is proven; exit 1 with `…: not proven (…)` is not
proven; exit 2, and any other answer (ssh, sudo or the installer failing, a status without its
verdict line), is no verdict: tried again every 10 seconds until `timeout` (a duration, default
`10m`) runs out. Not proven, or no verdict by then (the last run's error named), is an apply error
with `fail_if_not_proven` (the default): the state is saved tainted, so the next apply checks again.
With `fail_if_not_proven = false` it is a warning and `proven` false, for a `postcondition` or an
output.

**Refresh**: while `proven` is false, one run (no retry): a verdict is recorded; no verdict, or an
install that does not answer, keeps state as it is, with a warning. Once proven, nothing runs.
**Destroy** runs nothing.

A replaced target install keeps its `id` (`<work_dir>/<name>`, `<namespace>/<release>`): give the
check `replace_triggered_by` on it, so a new target is checked again.
