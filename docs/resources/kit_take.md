# stowage_kit_take (Resource)

A handoff kit taken by an install that exists: the install runs again given it (Docker: its kept installer `--kit FILE --kit-code-file FILE --no-input --json`; Kubernetes: `k8s upgrade --kit` by the installer of the release it runs; VM: `sudo -n <short_name>-stow install --kit … --no-input --json`), the kit and its code files on standard input. The provider never opens the kit: the install takes what it holds as `--given`'s. A create, or a change of `kit_wo_version`, takes the kit; a refresh runs nothing; destroying it forgets it, and the inputs it gave stay on the install. For a first install, give the kit to the install resource's `kit_wo` instead; this one is for an install that exists (a kit going back to the install that issued the other one).

## Example Usage

```terraform
# The install "issuer" exists: it takes the kit site B issued back by its re-run.
resource "stowage_kit_take" "issuer" {
  kit_wo         = ephemeral.stowage_kit.back.kit
  kit_code_wo    = ephemeral.stowage_kit.back.code
  kit_wo_version = stowage_kit.back.id # a new kit is taken again

  docker {
    host             = stowage_docker_install.issuer.host
    user             = stowage_docker_install.issuer.user
    known_hosts_line = stowage_docker_install.issuer.known_hosts_line
    install_id       = stowage_docker_install.issuer.id
    short_name       = stowage_docker_install.issuer.short_name
  }
}
```

## Details

The install that takes the kit is named by one block, as `stowage_kit`'s (`docker`, `kubernetes`,
`vm`): changing what names the install replaces the resource; a change of how it is reached alone
is recorded in place, nothing taken.

**Create, and a change of `kit_wo_version`**: refused before anything runs when `kit_wo` is null or
empty (`The kit is not here`: the ephemeral `stowage_kit` is null outside the apply that issued the
kit; bump the `stowage_kit`'s `version`) or `kit_code_wo` is (`kit_code_wo is not given`). Then the install runs again given the kit and its code as files on standard input,
in a private directory removed afterwards (`--kit FILE --kit-code-file FILE`): Docker, the kept
installer `<install_id>/<short_name>-stow --no-input --json --dir`; Kubernetes, `<name>.sh k8s upgrade
--no-input --json --namespace … --kit … --kit-code-file …` by the release's own installer (fetched and
checked; a release running another is refused, `The release runs another installer`), with the
provider's `registry_ca` and mirror login; VM, `sudo -n <short_name>-stow install --no-input --json`
over SSH. The provider never opens the kit: the installer takes what it holds as `--given`'s, and
refuses one it cannot (exit 3: the reason and fix, nothing recorded). `id` records the
`kit_wo_version` taken. Before anything is given, the install's status is read (Docker: the kept
installer's `status --json`; VM: `<short_name>-stow status --json`; Kubernetes: `k8s status --json`,
read again just before the take, its installer checked again: a release gone since is refused,
`the namespace holds no release … any more`): a Docker `install_id` whose directory holds no install is `No install there`, a Kubernetes
namespace holding no release `No release there`, and an
install whose first install has not finished (`installed` null: a VM answers from its seed's
installer before it, a Docker directory once its first install began) is `Nothing installed there`
— a take is a re-run, never a first install, which the install resource's `kit_wo` gives.

A key the kit gives that the install's resource also gives in `inputs` is the kit's on the install
from then on: the install resource's next refresh reads it (its record changed since the last
one, which the end of its last create or update keeps), and its next plan gives the configuration's
back. Give such a key in one place.

**Refresh** and **destroy** run nothing: what the kit gave stays on the install. A replaced install
takes the kit again only with a kit issued again (the `stowage_kit`'s `version` bumped, which
changes `kit_wo_version`); `replace_triggered_by` on the install would replace this resource at any
update of it, in an apply with no kit (`The kit is not here`).
