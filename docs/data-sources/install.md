# stowage_install (Data Source)

Reads an install's `status --json` without managing it: a Docker install (by the installer it keeps, `<work_dir>/<name>/<short_name>-stow status --json`) or a VM (`<short_name>-stow status --json`). Exactly one of the `docker` and `vm` blocks. Nothing on the target changes. A Kubernetes release is read by `stowage_install` (its read needs an installer image).

## Example Usage

```terraform
# What a Docker install runs, read without managing it (another root's install, a dashboard).
data "stowage_install" "notes" {
  name       = "notes"
  short_name = "notes"

  docker {
    host             = "app.example.com"
    user             = "ops"
    known_hosts_line = "app.example.com ssh-ed25519 AAAA..."
    work_dir         = "/srv"
  }
}

output "notes_version" {
  value = data.stowage_install.notes.installed.version
}
```

## Details

Reads an install's `status --json` without managing it: a Docker install by the installer it keeps
(`<work_dir>/<name>/<short_name>-stow status --json`, through the same scripts as the resource's
read) or a VM by its OS bundle's (`<short_name>-stow status --json`, as the SSH user). Nothing on
the target changes, and no installer image is fetched: a Kubernetes release, whose read needs one,
is read by the resource. The read is bounded by 5 minutes. Exactly one of the `docker` and `vm` blocks (`One target`); no install in
the directory (`No install`) and another project's (`Another project's install`) are errors.
